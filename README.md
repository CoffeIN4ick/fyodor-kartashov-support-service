\# Сервис заявок в службу поддержки



Учебный веб-сервис для работы с заявками в службу поддержки, разработанный в рамках домашнего задания №1 по дисциплине «Оптимизация клиент-серверных приложений».



Сервис позволяет создавать заявки, распределять их по категориям, вести переписку через комментарии, изменять статусы заявок и рассчитывать время реакции сотрудника относительно норматива категории.

\## Веб-интерфейс



Интерфейс позволяет:



\- выполнить вход;

\- создать заявку;

\- просмотреть список заявок;

\- фильтровать заявки по статусу;

\- фильтровать заявки по категории;

\- использовать постраничный вывод;

\- открыть карточку заявки;

\- просмотреть комментарии;

\- сотруднику — изменить статус заявки;

\- просмотреть сводку.



\## Бизнес-правила



Поддерживаются статусы:



```text

new

in\_progress

closed

```



Для каждой категории задан норматив времени реакции.



Временем реакции считается интервал между созданием заявки и первым комментарием сотрудника поддержки.



Если первый ответ сотрудника превышает норматив категории, заявка считается заявкой с нарушенным нормативом.



Сводка показывает:



\- общее количество заявок;

\- количество заявок с нарушением норматива;

\- долю нарушений;

\- количество открытых заявок по категориям.

\## Замеры времени ответа



Для измерения времени ответа используется PowerShell-скрипт:



```powershell

.\\measure.ps1

```



Скрипт:



\- выполняет авторизацию под учётной записью `demo`;

\- выполняет прогрев;

\- выполняет 30 повторов;

\- рассчитывает p50;

\- рассчитывает p95;

\- определяет максимальное время ответа.



Измеряются операции:



```text

GET /api/categories

GET /api/tickets?page=1\&size=20

GET /api/tickets/1

GET /api/summary

```



Результаты сохраняются также в CSV-файл.



\## Разложение времени между приложением и БД



Для измерения используется:



```powershell

.\\measure\_breakdown.ps1

```



Сервис добавляет в HTTP-ответы диагностические заголовки:



```text

X-Db-Queries

X-Db-Time-Ms

```



Они содержат количество SQL-запросов и суммарное время их выполнения.



Скрипт рассчитывает:



\- полное время операции;

\- время в PostgreSQL;

\- время в коде приложения;

\- количество SQL-запросов.



Для разложения анализируются:



```text

GET /api/tickets?page=1\&size=20

GET /api/summary

```



\## Программный интерфейс



| Метод и путь | Параметры | Ответ | Ошибки |

|---|---|---|---|

| `POST /api/login` | JSON: `username`, `password` | Данные пользователя и cookie авторизации | `401` |

| `POST /api/logout` | Нет | Сообщение об успешном выходе | `401` |

| `GET /api/me` | Нет | Данные текущего пользователя | `401` |

| `GET /api/categories` | Нет | Список категорий и нормативов | `401` |

| `GET /api/tickets` | `page`, `size`, `status`, `categoryId` | Страница заявок: `page`, `size`, `total`, `items` | `400`, `401` |

| `GET /api/tickets/{id}` | `id` | Карточка заявки, пользователь, категория, комментарии, время реакции и SLA | `401`, `404` |

| `POST /api/tickets` | JSON: `title`, `description`, `categoryId` | Созданная заявка | `400`, `401`, `404` |

| `POST /api/tickets/{id}/comments` | `id`, JSON: `text` | Созданный комментарий | `400`, `401`, `404` |

| `PUT /api/tickets/{id}/status` | `id`, JSON: `status` | Новый статус заявки и `closedAt` | `400`, `401`, `403`, `404` |

| `GET /api/summary` | Нет | Сводные показатели по заявкам | `401` |

\## Основные сценарии



\### Создание заявки пользователем



1\. Войти под учётной записью `demo`.

2\. Указать заголовок.

3\. Ввести описание проблемы.

4\. Выбрать категорию.

5\. Нажать «Создать заявку».

6\. Открыть созданную заявку в списке.



\### Обработка заявки сотрудником



1\. Войти под учётной записью `employee`.

2\. Открыть заявку.

3\. Добавить комментарий сотрудника.

4\. Перевести заявку в статус «В работе».

5\. После завершения перевести заявку в статус «Закрыта».



После первого ответа сотрудника сервис автоматически рассчитывает время реакции и проверяет соблюдение норматива категории.



\## Остановка сервиса



ASP.NET Core останавливается сочетанием:



```text

Ctrl+C

```



Контейнер PostgreSQL можно остановить командой:



```powershell

docker compose down

```



Данные PostgreSQL сохраняются в Docker volume.



Для полного удаления контейнера вместе с данными:



```powershell

docker compose down -v

```



Команду с `-v` следует использовать только тогда, когда требуется полностью удалить базу данных.
